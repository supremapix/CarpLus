# E6.5 — Validação do Preview na Vercel

Data: 2026-07-14
URL auditada: `https://carp-lus-git-v0-supremapix-155c8202-supremapixs-projects.vercel.app/`

## Veredito

**E6.5 PARCIAL — CORREÇÕES NECESSÁRIAS (bloqueio de infraestrutura)**

A auditoria real **não pôde ser executada**: o deployment de Preview está protegido pela
**Deployment Protection (SSO/Vercel Authentication)**. Todas as requisições são interceptadas e
redirecionadas (HTTP 302) para `vercel.com/sso-api` → `vercel.com/login` **antes** de chegarem à
aplicação. Nenhuma rota, asset, sitemap, robots ou resposta de bot é acessível externamente.

`location: https://vercel.com/sso-api?...`. Seguindo o redirect chega-se em
`<title>Login – Vercel</title>`.

## Como desbloquear a auditoria (escolher uma opção)

1. **Desativar a Deployment Protection** para este Preview:
   Vercel → Project **carp-lus** → Settings → **Deployment Protection** → desativar
   *Vercel Authentication* (ou mudar para "Only Production"). Reenviar a mesma URL.
2. **Protection Bypass for Automation** (mantém a proteção):
   Settings → Deployment Protection → **Protection Bypass for Automation** → gerar o secret e
   me fornecê-lo. A auditoria passará a incluir o header
   `x-vercel-protection-bypass: <secret>` em todas as requisições.
3. **Link compartilhável** sem proteção para a mesma URL de Preview.

## Observação importante sobre escopo

Além do bloqueio de SSO, é preciso confirmar que a env var **`GENERATE_STATIC=1`** está definida
no ambiente de Preview do projeto. Sem ela, o `buildCommand` (`build:deploy`, entregue na E7)
publica **apenas o SPA** — as 1.512 páginas físicas **não** seriam geradas mesmo com o acesso
liberado. Recomenda-se garantir `GENERATE_STATIC=1` **antes** de reexecutar a auditoria, para que
o item "1.512 páginas publicadas" possa ser verdadeiramente verificado.
