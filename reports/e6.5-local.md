## 3. Roteamento HTTP sobre o output real (REAL)

Servido o `dist/` com `scripts/e6-routing-server.mjs`, que replica a cadeia da Vercel
`redirects → filesystem → rewrite SPA` **e** aplica os `headers` do `vercel.json`.

- Redirects incondicionais 301: **75/75** com `Location` correto.
- Rotas físicas via filesystem (amostra 1 por tipo, 87 casos): **87/87** → 200 `X-Served-By: filesystem`.
- Casos de borda: `/pneus?page=2` → 301; `/pneus` nu → 200; medida dinâmica `/pneus/175-65r14` → 301; asset → 200; rota inexistente → 200 `spa-fallback-rewrite` (soft-404 esperado até a remoção do Prerender.io).
- Precedência **redirect > filesystem > rewrite** confirmada.
- **Total harness: 165/165 aprovados.**

## 4. Headers (REAL)

Verificado via `curl -D -` contra o servidor de emulação:
- `/` e páginas: recebem os headers globais de segurança (`X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `X-XSS-Protection: 1; mode=block`).
- `/sitemap.xml`: `Content-Type: application/xml` + `Cache-Control: public, max-age=86400` + segurança.
- **Observação não-bloqueante:** o `vercel.json` **não** define `Cache-Control` para `/assets/*`
  (arquivos com hash no nome). Recomendável adicionar `public, max-age=31536000, immutable`
  para cache ótimo de assets versionados. Fora do escopo da E6.

## 6. Middleware / bots / Prerender.io (REAL — lógica de decisão)

Em vez de "simular", executei a **lógica real** do `middleware.js` (`scripts/e6-middleware-decision.mjs`),
injetando um `fetch` mockado para não chamar a rede externa. 9/9 casos em dois cenários:

| Requisição | Sem token (ambiente atual) | Com token (produção) |
|---|---|---|
| Humano (qualquer rota) | fallthrough → FS/SPA | fallthrough → FS/SPA |
| Bot em página (`/`, produto, serviço) | fallthrough → SPA (rede de segurança) | **rewrite → Prerender.io** |
| Bot em asset/meta (`.js`, sitemap, robots, imagem) | fallthrough | fallthrough |

**CONCLUSÃO-CHAVE (REAL):** o middleware roda **antes** do filesystem. Para **bots** em
rotas de página, ele reescreve para o Prerender.io **antes** de alcançar as páginas físicas.
Portanto, enquanto o middleware estiver ativo:
- As 1.512 páginas físicas da E6 **beneficiam humanos** (200 via filesystem, hidratação limpa).
- **Bots continuam servidos pelo Prerender.io**, não pelas páginas físicas.
- A rede de segurança (SPA quando sem token, erro ou timeout de 10 s) permanece intacta.

Isso confirma que a **remoção do Prerender.io** (etapa final do roadmap) é o passo que
"liga" o benefício da E6 para bots — e agora há base estática pronta para isso.
