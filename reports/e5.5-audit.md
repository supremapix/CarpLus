## 4. Prebuild ponta a ponta

- `npm run build` completo: `prebuild` (sitemap → redirects) → `vite build`, **BUILD_EXIT=0**, `dist/` populado, `vercel.json` com 152 regras.
- **⚠ Observação não-bloqueante:** o passo de sitemap do `prebuild` ainda usa `tsx` (`tsx scripts/generate-sitemap.ts`), que é **no-op** neste sandbox (não regenera `public/sitemap*.xml`; a única diferença ao rodar via `run-ts.mjs` foi o `<lastmod>`, URLs idênticas). No build da Vercel o `tsx` funciona, então não há impacto em produção — mas há **inconsistência de runner** entre os dois passos. Recomendação (fora do escopo desta etapa): padronizar o sitemap para `run-ts.mjs`.

## 7. Comportamento de bots (middleware)

- Ordem na Vercel: **`redirects` (301) são avaliados ANTES do middleware** → bots recebem o 301 primeiro; o destino final é que passa pelo Prerender.io.
- Simulação da lógica real do `middleware.js`:
  - Usuário → routing normal (redirects → fs → rewrite).
  - Bot em rota HTML **com** `PRERENDER_TOKEN` → Prerender.io (short-circuit, Response 200).
  - Bot **sem** token → fallback SPA.
  - Bot em `/assets/*`, `/sitemap.xml` etc. → nunca pré-renderizado (passa direto).
- Rede de segurança para bots **intacta**; E5 não a alterou.
