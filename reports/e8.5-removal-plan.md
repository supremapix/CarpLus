## FASE 2 — Ordem exata de remoção (nunca tudo de uma vez)

```
1  Definir PRERENDER_ENABLED=false em PREVIEW  ─┐  (não toca código)
                                                │
2  Validar bots no edge real (Preview)         │  ← porta de decisão
                                                │
3  Definir PRERENDER_ENABLED=false em PRODUÇÃO ─┘  (desvio desligado, código intacto)
        ↓  (monitorar 14-30 dias — ver Fase 4)
4  Remover dispatch 'render-event'  (useSEO.ts:137)
        ↓
5  Remover metas prerender-token / prerender-status-code  (index.html:19-23)
        ↓
6  Remover variável de ambiente PRERENDER_TOKEN
        ↓
7  Remover middleware.js (+ PRERENDER_ENABLED) e cancelar assinatura Prerender.io
        ↓
8  Limpeza final: comentários residuais + validação de build/SSG
```

Regra: **um passo por deploy**, cada um com verificação e janela de observação antes do próximo.
Os passos 1-3 são **reversíveis por env var** (sem tocar código).

## FASE 3 — Por remoção: riscos, rollback, tempo, impacto

### Passo 1-2 — `PRERENDER_ENABLED=false` em Preview + validação de bots
- **Riscos:** Preview bloqueado por SSO impede a auditoria (situação atual); HTML físico divergir do Prerender.io.
- **Rollback:** remover a env var (< 2 min); nenhum código alterado.
- **Tempo:** ~15 min de configuração + auditoria.
- **Impacto:** nenhum em produção.

### Passo 3 — `PRERENDER_ENABLED=false` em Produção
- **Riscos:** bots passam a receber HTML físico; se alguma rota estiver como shell (ver bug da home E8, já corrigido) o SEO cai.
- **Rollback:** `PRERENDER_ENABLED=true` + redeploy (< 5 min).
- **Tempo:** deploy + 14-30 dias de observação.
- **Impacto:** alto se algo falhar — por isso a longa janela e o rollback por env var.

### Passo 4 — Remover `render-event` (`useSEO.ts:137`)
- **Riscos:** baixíssimo — o sinal só era consumido pelo serviço, já desligado.
- **Rollback:** git revert do arquivo (< 5 min).
- **Tempo:** ~10 min + build.
- **Impacto:** nenhum funcional; não afeta o `__STATIC_RENDER_READY__` da SSG.

### Passo 5 — Remover metas Prerender (`index.html:19-23`)
- **Riscos:** baixo — só relevantes para o serviço. Remove o **token exposto no HTML** (ganho de segurança).
- **Rollback:** git revert (< 5 min). O build regenera `reports/_spa-shell/index.html`.
- **Tempo:** ~10 min + build.
- **Impacto:** positivo (segurança).

### Passo 6 — Remover env `PRERENDER_TOKEN`
- **Riscos:** se o middleware ainda existir e for reativado, cai no fallback SPA (não quebra).
- **Rollback:** re-adicionar a variável (< 5 min).
- **Tempo:** ~5 min.
- **Impacto:** nenhum (desvio já desligado).

### Passo 7 — Remover `middleware.js` + cancelar assinatura
- **Riscos:** perda do rollback rápido por env var (a rede de segurança deixa de existir). Só executar após 30 dias estáveis.
- **Rollback:** restaurar `middleware.js` via git + re-adicionar `PRERENDER_TOKEN` (< 15 min); reassinar serviço se cancelado.
- **Tempo:** ~15 min + deploy.
- **Impacto:** elimina a dependência externa e o custo recorrente.

### Passo 8 — Limpeza final
- **Riscos:** nenhum (comentários e texto).
- **Rollback:** git revert.
- **Tempo:** ~15 min.
- **Impacto:** cosmético/organização.

## FASE 4 — Search Console: quando é seguro remover

**Premissa:** o desvio de bots (passo 3) é o ponto de não-retorno funcional. A remoção de código
(passos 4-7) só ocorre depois que o Search Console confirmar que o Googlebot está indexando o
**HTML físico** com a mesma qualidade do Prerender.io.

Sinais a observar após ativar `PRERENDER_ENABLED=false` em produção:

| Janela | O que observar | Sinal de sucesso | Sinal de alerta (rollback) |
|---|---|---|---|
| **24h** | "Testar URL ao vivo" (home + 1 de cada tipo); logs do middleware | HTML renderizado = físico; 0 fallback inesperado | Página vazia/shell; erros 5xx |
| **72h** | Páginas rastreadas recentemente; status de rastreamento | Googlebot busca HTML físico; sem pico de erros | Queda de "Rastreada – não indexada" |
| **7 dias** | Cobertura (Válidas/Excluídas); Rich Results | Contagem estável; JSON-LD válido | Aumento de "Excluídas"; perda de rich results |
| **14 dias** | Impressões/cliques (Desempenho); canônicas | Métricas estáveis ou melhores | Queda sustentada de impressões |
| **30 dias** | Cobertura total; indexação das 1.512 URLs | Indexação ≥ linha de base pré-mudança | Regressão de indexação |

**Regra:** só avançar para os passos 4-7 (remoção de código) após **≥14 dias** sem alertas, e
para o passo 7 (remover middleware + cancelar assinatura) após **30 dias** estáveis.
