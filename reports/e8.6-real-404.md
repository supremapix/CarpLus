# E8.6 — 404 HTTP real (fim do soft-404)

Data: 2026-07-14. Objetivo: eliminar o soft-404 (todas as rotas retornavam HTTP 200) e passar a
responder **404 real** para rotas inexistentes, sem quebrar nenhuma rota válida.

## 1. Diagnóstico da causa raiz

O soft-404 vinha do **catch-all rewrite** em `vercel.json`:
```json
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```
Ordem de resolução na Vercel: **redirects (301) → filesystem (200) → rewrites → 404.html nativo**.
Como `/(.*)` casa com tudo, o `404.html` nativo **nunca** era alcançado; qualquer URL desconhecida
recebia o shell SPA com **200**. O React Router (`<Route path="*" element={<NotFound/>}>`) renderiza
a 404 client-side com `noindex`, mas o status HTTP já saíra como 200 → **soft-404**.

**Conflito arquitetural:** o catch-all não era descartável — era o fallback SPA de rotas válidas
**não** pré-geradas (institucionais, promoção, `/admin`, `/sitemap`, dinâmicas). Removê-lo sem
reintroduzir esses caminhos quebraria páginas válidas.

**Decisão do usuário:** pré-gerar/rotear todas as válidas + `404.html`, removendo o catch-all.
Como `getStaticRoutes()` é compartilhado com o `sitemap.xml` (não pode ser poluído) e a geração de
indexáveis não podia ser alterada, as rotas válidas não-físicas foram cobertas por **rewrites
explícitos** (equivalente ao fallback SPA anterior, mas restrito às rotas conhecidas).

## 2. Mudanças aplicadas (mínimas, aditivas)

| Arquivo | Mudança |
|---|---|
| `vercel.json` | catch-all `/(.*)` substituído por 8 rewrites explícitos das rotas válidas não-físicas (`/pneus-promocao`, `/pneu-promocao/:slug`, `/politica-de-privacidade`, `/trocas-e-devolucoes`, `/sitemap`, `/admin/:path*`, `/bairro/:slug`, `/servico/:slug`) |
| `scripts/build-deploy.mjs` | `emit404()` copia o shell SPA limpo para `dist/404.html` logo após `build:spa` |
| `src/hooks/useSEO.ts` | prop opcional `prerenderStatusCode` (aditiva) que cria/remove `<meta name="prerender-status-code">`; removida no cleanup para não vazar em navegação SPA |
| `src/components/NotFound.tsx` | passa `prerenderStatusCode: 404` (bots via Prerender.io recebem 404 enquanto o middleware existir) |

**Não alterado:** geração de páginas indexáveis, sitemap, redirects (301), robots.txt, llms.txt,
layouts, conteúdo. O `generate-redirects.ts` preserva `rewrites` — a mudança sobrevive ao build.

## 4. Validação de bots e SPA (browser real)

- Na 404: `title` correto, `robots = noindex, follow`, `prerender-status-code = 404`, `<h1>` presente.
- Após navegar (SPA) da 404 → home: `prerender-status-code` volta a `200` e `robots` a `index, follow`.
  **O status 404 não vaza** para outras rotas.
